    31→#### SEC-001 — CRITICAL — Caddyfile open reverse-proxy (SSRF)
    32→- **File:** `Caddyfile:6-13`
    33→- **Problem:** The Caddyfile accepts any request with query parameter `?XTransformPort=<port>` and reverse-proxies it to `localhost:<port>`. An external attacker can craft URLs like `https://<deployed-host>/?XTransformPort=5432` to reach PostgreSQL, `XTransformPort=6379` for Redis, `XTransformPort=9000` for PHP-FPM, internal admin panels, the Prisma SQLite RPC, metadata services, etc. — any TCP listener on the host.
    34→- **Root cause:** The `@transform_port_query` matcher + `reverse_proxy localhost:{query.XTransformPort}` block trusts a user-controlled query parameter as the upstream target with no allowlist.
    35→- **Impact:** Full SSRF — attackers can pivot into every local service, exfiltrate database contents, hit cloud-metadata endpoints (169.254.169.254), scan internal network, bypass firewalls. This is the single most severe finding in the audit, and it is in the deployment config that ships with the repo.
    36→- **Recommended fix:** Remove the dynamic-port block entirely, or replace it with an explicit allowlist (e.g. `:3000`, `:3003` only). At minimum, restrict to known safe ports:
    37→  ```caddyfile
    38→  @allowed_port query XTransformPort=3000
    39→  query XTransformPort=3003
    40→  handle @allowed_port { reverse_proxy localhost:{query.XTransformPort} }
    41→  ```

    45→#### SEC-002 — HIGH — No Content-Security-Policy or security headers
    46→- **File:** `next.config.ts:3-10`
    47→- **Problem:** `next.config.ts` defines only `output: "standalone"`, `typescript.ignoreBuildErrors`, and `reactStrictMode: false`. There is **no `headers()` configuration**, so the deployed app ships with **no** `Content-Security-Policy`, no `X-Frame-Options`/`frame-ancestors`, no `X-Content-Type-Options: nosniff`, no `Referrer-Policy`, no `Permissions-Policy`. The app calls `getDisplayMedia`/`getUserMedia` — without a `Permissions-Policy` that explicitly allows them only on this origin, third-party iframes/ embedders can attempt to frame the page and request camera/mic/screen.
    48→- **Root cause:** Default Next.js config doesn't add security headers; developer must opt in.
    49→- **Impact:** (1) If any XSS is ever introduced (now or by a future dependency), there is no CSP to contain it. (2) Clickjacking — page can be iframed by attackers. (3) MIME-sniffing attacks. (4) Permission prompts can be triggered from framed contexts.
    50→- **Recommended fix:** Add a `headers()` block to `next.config.ts`:
    51→  ```ts
    52→  const nextConfig: NextConfig = {
    53→    async headers() {
    54→      return [{
    55→        source: "/(.*)",
    56→        headers: [
    57→          { key: "Content-Security-Policy",
    58→            value: "default-src 'self'; script-src 'self' 'unsafe-inline'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:; media-src 'self' blob:; connect-src 'self'; frame-ancestors 'none'; base-uri 'self'" },
    59→          { key: "X-Frame-Options", value: "DENY" },
    60→          { key: "X-Content-Type-Options", value: "nosniff" },
    61→          { key: "Referrer-Policy", value: "strict-origin-when-cross-origin" },
    62→          { key: "Permissions-Policy",
    63→            value: "camera=(self), microphone=(self), display-capture=(self), geolocation=(), clipboard-write=(self)" },
    64→        ],
    65→      }];
    66→    },
    67→  };
    68→  ```

   102→#### SEC-005 — MEDIUM — Watermark logo upload accepts SVG (script-injection footgun)
   103→- **File:** `src/components/recorder/control-panel.tsx:642`
   104→- **Problem:**
   105→  ```tsx
   106→  <input type="file" accept="image/png,image/jpeg,image/svg+xml" ... />
   107→  ```
   108→  SVG files can contain `<script>` tags and event handlers (`onload`, `onerror`). The uploaded file is read via `FileReader.readAsDataURL` (`control-panel.tsx:653`) and stored as `watermarkLogoDataUrl`. Currently the data URL is consumed in two XSS-safe ways: (1) `<img src={dataUrl}>` at `control-panel.tsx:675` (img tags don't execute SVG scripts), and (2) `new Image()` + `ctx.drawImage()` at `use-recorder.ts:368,730` (canvas drawImage doesn't execute scripts either). **Today this is safe**, but it is a footgun — any future code path that renders the data URL via `<embed>`, `<object>`, `<iframe>`, `<a target=_blank href={dataUrl}>`, `fetch(dataUrl).then(r => r.text())` then `innerHTML`, or top-level navigation would execute attacker-controlled script in the app origin.
   109→- **Root cause:** SVG is included in the accept list without a clear need (the watermark feature wants raster logos).
   110→- **Impact:** Latent XSS — depends on future code changes. Also, SVGs can carry XXE payloads that affect some parsers (not the browser's `<img>` loader, but defense-in-depth is wise).
   111→- **Recommended fix:** Drop SVG from the accept list:
   112→  ```tsx
   113→  accept="image/png,image/jpeg,image/webp"
   114→  ```
   115→  And validate the data URL prefix in the `onload` handler:
   116→  ```ts
   117→  reader.onload = () => {
   118→    const dataUrl = reader.result as string;
   119→    if (!/^data:image\/(png|jpeg|webp);base64,/.test(dataUrl)) return;
   120→    if (dataUrl.length > 1_500_000) { toast({ description: "Logo too large (max 1 MB)" }); return; }
   121→    rec.updateSettings("watermarkLogoDataUrl", dataUrl);
   122→  };
   123→  ```

   145→#### SEC-008 — MEDIUM — localStorage prefs JSON.parse has no schema validation
   146→- **File:** `src/hooks/use-recorder.ts:195-206, 353-357`
   147→- **Problem:**
   148→  ```ts
   149→  function loadPrefs(): Partial<PersistablePrefs> | null {
   150→    const raw = window.localStorage.getItem(PREF_KEY);
   151→    if (!raw) return null;
   152→    const parsed = JSON.parse(raw);
   153→    if (!parsed || typeof parsed !== "object") return null;
   154→    return parsed as Partial<PersistablePrefs>;   // ← no field-type validation
   155→  }
   156→  // ...
   157→  const prefs = loadPrefs();
   158→  if (prefs) {
   159→    setSettings((prev) => ({ ...prev, ...prefs }));   // ← blind spread
   160→  }
   161→  ```
   162→  Any value (correct type, wrong type, extra fields, malicious `__proto__`-like keys) is accepted and spread over `DEFAULT_SETTINGS`. Downstream consumers assume typed fields:
   163→  - `drawWatermark` at `use-recorder.ts:702` calls `s.watermarkText?.trim()` — crashes if `watermarkText` is a number.
   164→  - `Math.round(h * s.watermarkLogoSize)` at `:712,723` returns `NaN` if `watermarkLogoSize` is a string.
   165→  - Slider components receive non-number values and may render NaN.
   166→  A malicious script on the same origin (e.g., via an XSS in a future dependency, or another app hosted on the same origin) could plant `localStorage.setItem("wpr-prefs-v1", JSON.stringify({watermarkText: 12345, quality: "4320", frameRate: "999"}))` to crash the recorder on next load — a persistent client-side DoS.
   167→- **Root cause:** `JSON.parse` + bare cast without runtime validation.
   168→- **Impact:** Persistent client-side DoS via crafted localStorage; potential crashes if attackers can write to localStorage.
   169→- **Recommended fix:** Validate each field by type and range before merging, e.g.:
   170→  ```ts
   171→  function loadPrefs(): Partial<PersistablePrefs> | null {
   172→    try {
   173→      const raw = window.localStorage.getItem(PREF_KEY);
   174→      if (!raw) return null;
   175→      const p = JSON.parse(raw);
   176→      if (!p || typeof p !== "object" || Array.isArray(p)) return null;
   177→      const out: Partial<PersistablePrefs> = {};
   178→      if (typeof p.watermarkText === "string") out.watermarkText = p.watermarkText.slice(0, 200);
   179→      if (typeof p.watermarkOpacity === "number") out.watermarkOpacity = clamp(p.watermarkOpacity, 0.1, 1);
   180→      if (typeof p.watermarkSize === "number") out.watermarkSize = clamp(p.watermarkSize, 0.01, 0.06);
   181→      if (typeof p.watermarkLogoSize === "number") out.watermarkLogoSize = clamp(p.watermarkLogoSize, 0.02, 0.15);
   182→      if (["text","logo","both"].includes(p.watermarkMode)) out.watermarkMode = p.watermarkMode;
   183→      if (["720","1080","1440","native"].includes(p.quality)) out.quality = p.quality;
   184→      if (["24","30","60"].includes(p.frameRate)) out.frameRate = p.frameRate;
   185→      // ... and so on for each persistable field
   186→      return out;
   187→    } catch { return null; }
   188→  }
   189→  ```
